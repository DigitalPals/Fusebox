## Behavior

The account drawer and desktop/mobile detail pages show **Clear error** beside
**Last error**, including errors without cooldowns. The action disables while
saving and reports success only after the server accepts it. Save failures are
shown separately from the original provider error. The Claude third-party
billing message also offers a fixed link to its usage settings.

`POST /api/accounts/{id}/error/clear` uses existing management authentication
and requires the displayed `last_error_id` as `error_id`. Each recorded error
occurrence has a fresh UUID; a newer occurrence, including the same message
repeated, returns 409 instead of being dismissed. The action preserves quota,
cooldowns, strikes, account enablement, counters and request history, sends no
provider request and broadcasts an account update. Existing cooldown reset
behavior remains available separately.
